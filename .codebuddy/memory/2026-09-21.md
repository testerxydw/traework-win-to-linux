## MCP 服务全部"已关闭"根因与修复（slim 误删跨平台 Node 代码）

### 现象
用户报告「MCP 三个服务（GitHub / gitee / gitlab）全部 Server 已关闭」，弹窗"原始错误信息：扩展进程崩溃或已退出"。

### 根因（已确证）
slim 规则按**任意路径**匹配：`find "$BASE" -path '*win32*' -prune -exec rm -rf {} +`
误删【跨平台 Node 代码】而非平台二进制：
```
node_modules/which/node_modules/isexe/dist/cjs/win32.js
node_modules/which/node_modules/isexe/dist/mjs/win32.js
```
（`isexe/dist/cjs/index.js:32` 有 `require("./win32.js")`，按平台动态加载实现）

→ 扩展宿主启动 `Error: Cannot find module './win32.js'`（MODULE_NOT_FOUND）→ `exit code: 1`
→ `McpService Extension host crashed` / `recovered from crashed, restarting all MCP` 循环
→ 扩展与 MCP 全部不可用；UI 那句"扩展进程崩溃或已退出"**是准确的**。

### 排查中的排除项（避免误判）
| 怀疑点 | 实测结果 |
|---|---|
| 网络不通 | curl 三个 MCP 地址 = 405/401/401（**可达**，非超时）→ 排除 |
| OAuth 未授权 | 日志确有 `authentication failed` / `No token data found`，但那只是**宿主崩溃后的表象** |
| Electron 版本不匹配 | 转制包与官方 `/usr/share/trae-cn` **均为 39.2.7** → 排除 |
| 原生模块是 Windows 版 | 20 个 `.node` **全部 ELF** → 排除 |
| 段错误崩溃 | Crashpad **无转储**，是主动 `exit 1` → 排除 |

1. **规则精确化**：删除一律限定 `-type d`，只删【目录名】带平台后缀的预编译产物目录

## 进程名 `trae-solo-cn-bi` 与 WM_CLASS 核实（用户问"是否少了 n"）

- **不是少字母**：Linux 内核 `comm` 字段上限 **15 字符**，而 `trae-solo-cn-bin` 是 **16 字符**
  → `top` / 任务管理器只能显示 `trae-solo-cn-bi`；`argv[0]` 与 `ps -o args` 均为完整路径
  `/opt/trae-solo-cn/trae-solo-cn-bin`。
- 命名设计（`build.sh:247`）：launcher 叫 `trae-solo-cn`（与 desktop 的 `Exec` 一致），
  真 Electron 二进制 `cp -f "$TRAECODE/trae-cn" → trae-solo-cn-bin`（加 `-bin` 后缀避免与 launcher 重名）；
  包内两文件都在：`opt/trae-solo-cn/trae-solo-cn` + `opt/trae-solo-cn/trae-solo-cn-bin`。
- **附带发现（未修，待用户决定）**：desktop 里 `StartupWMClass=trae-solo-cn`，但实测窗口
  `WM_CLASS = "trae-solo-cn-bin", "Trae-solo-cn-bin"` → **不匹配**（另一个窗口是 `"TRAE SOLO CN"`）。
  官方惯例用的是**产品显示名**：`trae-cn.desktop → StartupWMClass=Trae CN`、
  `code.desktop → Code`、`buddycn.desktop → CodeBuddy CN`。
  两种修法：① desktop 改 `StartupWMClass=trae-solo-cn-bin`（跟实测值走）；
  ② launcher 加 `--class=trae-solo-cn`（desktop/图标名保持一致，更规范）。
  DDE 目前图标与分组未见异常（DDE 还会用 `_NET_WM_PID` + 可执行路径反查 desktop），故不紧急。
