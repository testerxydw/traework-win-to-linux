## WorkBuddy Windows → Linux 移植（实际完成，GUI 可跑）
- 源材料（用户下载）：`WorkBuddy-win32-x64-user-5.3.14.36279234-825709d4.exe`(396M)、`CodeBuddy-linux-x64-4.11.2.36529961-74e2511a-cn.deb`(151M)。
- 产物：`workbuddy-build/workbuddy_5.3.14-1_amd64.deb`(270M)，已安装，`WorkBuddy` 窗口 1200x800 正常显示、进程稳定、CellJS 主框架初始化完成。
- 架构认知：WorkBuddy 是**自定义 Electron 应用**（入口 `main/index.js`），非 VS Code 分支，无 `out/main.js`；`main/*.js` 是 webpack bundle，纯 JS 依赖已打包，运行时只依赖 `app.asar.unpacked` 的原生模块。
- 移植三要素：Windows `app.asar`(自拆) + CodeBuddy Linux 的 Electron 37.7.0(ABI 136) 运行时 + Linux 原生模块。
- 原生模块处理：koffi 自带 linux_x64（免改）；better-sqlite3 自编译（Electron ABI 136）；node-pty 用 npm `@lydell/node-pty-linux-x64`；qimei-node（腾讯私有，npm 装不到）做 stub；wechat-copydata-decoder 代码已有 try/catch 自动降级。
- 遗留：daemon 子进程 SIGSEGV（以 `ELECTRON_RUN_AS_NODE=1` 跑 Node22 ABI127，与 Electron ABI136 模块不兼容；段错误在原生层，JS try/catch 拦不住）。属"部分功能可用"的正常预期，与社区结论一致。
- 技能固化：新增 `docs/skills/workbuddy-linux-port/SKILL.md`，软链安装到 `~/.codebuddy/skills/workbuddy-linux-port`；提交 `9e92058`。
