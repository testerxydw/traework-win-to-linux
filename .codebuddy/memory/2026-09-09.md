# 2026-09-09

## 修复 trae-solo-cn 0.1.63-1 打不开（标题栏补丁失效）

- 现象：新构建的 0.1.63-1 安装后无法打开窗口；启动日志在 `web-contents-created` 后抛
  `Error: Titlebar overlay is not enabled`（main.js `Pw.updateWindowControls`）。
- 根因：0.1.63 main.js 混淆名变化导致 build.sh 的三处标题栏补丁部分失效：
  1. 补丁①未命中：标题栏解析函数 0.1.58=`oW` / 0.1.61=`hV` → 0.1.63=`bV`，主进程仍强制
     `custom` → frame:false 无边框且无 overlay → updateWindowControls 抛异常，窗口起不来。
  2. 补丁②被污染：替换产物写死 `Lt||Object.assign(l,{titleBarOverlay:...})`，而 0.1.63 中
     `Lt` 是字符串 `"[MainGtmService]"`（恒真）→ overlay 永不设置。
  3. isLinux 变量 0.1.58/61=`Lt` → 0.1.63=`Qf`（定义 `Qf=Eo.platform==="linux"`，全文件唯一）。
- 修复（build.sh stage_extract 内 main.js 补丁重写为动态探测，不再写死变量名）：
  - isLinux：正则 `([A-Za-z_$][\w$]*)=[A-Za-z_$][\w$]*\.platform==="linux"` 取第一组。
  - 解析函数：通用正则 `function X(t){if(Y)return"custom";const e=t.getValue("window")`（实测唯一），
    按版本自动命中 oW/hV/bV 及未来新名。
  - **插入点坑**：必须在 `return"custom";` 的分号后插入；第一版插在 `const e=t.getValue("window")`
    尾部导致 `...getValue("window")if(Qf)...` → `SyntaxError: Unexpected token 'if'`（已踩坑修复）。
- 验证：`node --check main.js` 语法 OK → 启动无 Titlebar 异常 → xdotool 确认 `TraeWork CN` 窗口显示。
- 产物：`trae-solo-cn_0.1.63-2_amd64.deb`(256M) 已构建并安装（0.1.63-1 作废可删）。
- 非阻塞残留告警：① `EMFILE/inotify_init failed 打开文件过多`——文件监视降级，系统 inotify
  实例上限 128、各进程占用正常（WPS 5 个最多），非致命；② `OauthService:UserInfoNotMatchError`
  ——旧登录 token 与 0.1.63 校验不匹配，应用内重新登录即可。
- 环境备忘：本机无 `wmctrl`，查窗口用 `xdotool search --name "." getwindowname %@`。

## 0.1.63 官方 Linux 标题栏处理评估（用户目视确认，保留补丁）
- **结论修正**：0.1.63 官方代码在 Linux 上窗口能正常打开（实测原始 main.js 无 Titlebar 异常）。
  0.1.63-1 打不开的元凶是**本仓库补丁②写死 Lt 污染了官方 overlay 赋值**，非官方缺处理。
- 官方对 Linux 的"处理"= 与 Windows 同款自绘标题栏：`titleBarStyle="hidden"` + 非 mac
  `frame=!1` + `titleBarOverlay={height:29,color:p,symbolColor:b}`。新增的
  `forceNativeTitlebar` 仅用于 DevTools/对话框等辅助窗口，主窗口不走。
- **用户目视确认：官方自绘顶栏在 DDE 上仍有白块/异常**（0.1.58 时代问题未根治）→
  决定**保留补丁**（强制 native，DDE 系统标题栏）。补丁每版仍需维护，动态探测已降低成本。
