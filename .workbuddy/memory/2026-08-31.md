# 2026-08-31 工作记录

## WorkBuddy Linux deb 打包修复（-3 不能启动）

### 背景
- `workbuddy_5.3.14-2_amd64_old.deb`（能启动）vs `workbuddy_5.3.14-3_amd64.deb`（不能启动）。
- 两包 `app.asar` 与 `workbuddy-bin` **字节完全相同**；差异全在 `app.asar.unpacked`。
- -3 仅 295 文件 / 138MB；-2 有 1493 文件 / 284MB。-3 把 app.asar.unpacked 砍掉 1230 文件。
- `app.asar` 运行时 require 这些被删模块（weixinpay 272处、qimei 87处、node-pty 34处…）→ 启动崩溃。

### 根因（build-workbuddy.sh 的 stage_extract）
- 3c 只复制 `app.asar`；3d 只从编译产物拼 3 个 Linux 原生模块（better-sqlite3/koffi/node-pty）。
- **完全丢弃了 Windows 源 `app.asar.unpacked` 里的全部 JS 插件/资源**（plugins/cli/node_modules 等），导致运行时依赖缺失。
- 附带 bug：3d 原只 overlay 单包、漏掉传递依赖 bindings/file-uri-to-path；且 `linux_native/node_modules` 路径判断有误（真正在 `workbuddy-build/linux_native/...`）。

### 修复（已改 build-workbuddy.sh）
- 3c-2：整体 `rsync` Windows 源 `resources/app.asar.unpacked` 进包（脚本本就解包 Windows 源，**不依赖 -2**）。
- 3d：外科手术式 overlay 5 个运行期必需原生模块（better-sqlite3、bindings、file-uri-to-path 来自 `workbuddy-build/linux_native/node_modules`；koffi、@lydell 来自 `workbuddy-build/native_build/node_modules`）。**不要整树 overlay**（曾误带 node/tar-fs 等构建工具，撑爆 /tmp）。
- 3d-2：清理纯 Windows/mac 二进制（.exe/.dll/.pdb/.dylib/.framework/.app）瘦身，保留 JS 与 .node。

### 验证产物
- `workbuddy-build/workbuddy_5.3.14-5_amd64.deb`（172MB，1483 文件，md5sum 0 失败）。
- 与 -2 对比：缺口仅 42 个 = 19dll+16exe+2pdb（清理掉的 Win 二进制）+ 4 冗余 prebuild .node + 1 .orig；无任何启动必需文件缺失。
- 用 `bash build-workbuddy.sh --extracted workbuddy-build/wb_extract/app64 --no-install` 离线构建（原生模块已缓存，复用 runtime-cache）。

### 注意
- `rm` 被环境 shim 拦截（/opt/workbuddy/.../safe-bin/rm 权限不够），需用 `/bin/rm`。
- 之前用 -2 内容直接覆盖产出的 `workbuddy_5.3.14-3-fixed_amd64.deb`（283MB）仍保留作兜底，但 -5 才是真正 -2 无关的修复。

### 补充：沙箱里 workbuddy-bin "bad option" 的真因 + 启动实测
- 直接 `./workbuddy-bin --no-sandbox` 报 "bad option"、无参进 Node REPL，并非二进制问题，而是**本环境（WorkBuddy 自身运行环境）预设了 `ELECTRON_RUN_AS_NODE=1`**，使 Electron 主二进制退化为 node 模式。
- 用 `env -u ELECTRON_RUN_AS_NODE ./workbuddy`（或二进制）即可正常进入 Electron 主进程。真实用户桌面无此变量，正常 `sudo dpkg -i` 后运行 `workbuddy` 即可。
- **启动实测（/tmp/wb-test 模拟安装 -5，不碰系统）**：
  - `dpkg-deb -x workbuddy_5.3.14-5_amd64.deb /tmp/wb-test`，改 `workbuddy` 脚本的 `APP_DIR` 指向测试目录。
  - `env -u ELECTRON_RUN_AS_NODE xvfb-run -a ./workbuddy` 能进入主进程，日志注册 AccountService / NetProxy / TencentDocsThemeBridge / TencentDocsLanguageBridge，**无任何 Cannot find module / MODULE_NOT_FOUND / SIGSEGV** → 证明 -5 的 app.asar.unpacked 补全成功、可启动。
  - 唯一非致命提示：`xdg-settings: invalid application name`（设置默认应用的小警告，无影响）。
